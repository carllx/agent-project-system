# Context Relay (交接机制)

本工作流定义了在多轮交互达到上限、Agent 切换或强制挂起时，如何进行上下文的状态保存与流转。

## 触发条件

- 单个 RR Loop 已经达到默认六次循环上限，任务尚未 `ACHIEVED`。
- 探测到明显的“目标漂移”或死循环现象。
- 遇到硬性 `BLOCKED`，不得不等待外部依赖解决。
- 进入 `NEEDS_DECISION` 状态并长时间等待用户反馈。

## 交接原则

1. **零遗漏**：核心目标、已确认的本地事实与产生的结论不能在流转中丢失。
2. **轻量化**：禁止长篇大论的无用记录，必须使用精炼的总结与链接。
3. **断点续传**：下一个接手的 Agent 必须能凭借 Handoff 立即理解“我在哪”、“我要做什么”。

## 执行步骤

1. **暂停判断**：当达到六轮交互（或触发其他条件），IDE Agent 和 RR Lead 停止当前循环动作。
2. **状态固化**：
   - IDE Agent 负责将本地改动提交到暂存区或进行 stash。
   - IDE 收集最近的运行状态。
3. **编写 Handoff 包**：
   - IDE Agent 基于 `templates/handoff.md` 模板填写当前接力棒的状态。
   - 将 Handoff 存入 `state/` 目录或发送给对应接收方。
4. **切换状态**：
   - 将 `active-work-item.md` 状态变更为 `STALLED` 或 `NEEDS_DECISION`。
   - 等待唤醒。
