# 系统架构与角色边界 (Architecture & Boundaries)

本文档描述系统中三方角色的信息流转与权力边界，以及当前的架构限制。

## 角色交互拓扑

```mermaid
graph TD
    User([用户]) -- 设定目标/决策授权 --> RR_Lead
    RR_Lead[RR Lead (浏览器端)] -- 调研/技术判断/指令下发 --> IDE_Agent
    IDE_Agent[IDE Agent (本地端)] -- 测试证据/Diff/事实纠偏 --> RR_Lead
    RR_Lead -- 决策请求/状态汇报 --> User
```

## 三方角色权力边界

1. **User (最终裁决层)**
   - 掌握系统最高控制权和决策权。
   - 定义项目整体走向、隐私要求和资源成本上限。

2. **RR Lead (规划与调度层)**
   - 掌握任务分解、外部资料检索及技术路线选择权。
   - **越权限制**：不能脱离用户目标进行无效发散；不能无视本地 IDE 提供的运行事实强行推送方案；不可要求读取本地敏感凭证。

3. **IDE Agent (执行与事实层)**
   - 掌握本地代码文件编辑、命令执行、验证权。
   - **越权限制**：不能偏离 RR Lead 设定的 Next Step 擅自修改无关文件；不能隐藏本地报错事实；不能向外部随意发包或安装未获授权的依赖。

## 信息交流载体

整个系统基于结构化文档进行状态传递，主要使用文本及摘要：

* **Context Packet**: 传递全局背景、目标及初始技术分析。
* **Change Packet**: 传递代码执行变更 (Git Diff) 及测试结果证据。
* **Decision Request**: 传递给用户的白话选项。
* **Handoff**: 当任务流转或暂停时，用于接力的上下文快照。

## 当前架构限制 (MVP)

1. **并行限制**：当前系统为单线程模式，任何时刻仅有一个 Active Work Item 存在，不支持多任务并行调度。
2. **连接限制**：因现有 OpenCLI 的自动文件上传功能不稳定，禁止直接传输复杂的大体积项目文件，双方通信降级为使用文本摘要与精简版的 Git Diff。
3. **隔离限制**：浏览器端与本地端互相隔离，RR Lead 无法直接控制 IDE，IDE 也无法反向操控浏览器，必须通过协议化的 Packet 进行协作。
4. **服务集成限制**：暂不集成 GitHub 等三方代码托管与通知服务。
